# From Hardware to Operating Systems

## A Very Brief History of Computing

If you are mainly interested in learning how to program against modern UNIX-like systems, you can skip this historical section on a first pass. It is included for readers who might be curious about how digital computing and operating systems reached their current form. The details are not required for day-to-day system programming, but they help put modern abstractions—processes, files, virtual memory, signals, networking—into perspective: these interfaces were not designed in the abstract, they were shaped by concrete technical constraints and institutional choices over several decades.
The purpose of this short perspective is to make the present system landscape look less arbitrary: why the UNIX process model looks the way it does, why C remains the “native” interface to system calls, why network transparency mattered early, and why 64-bit address spaces were a turning point for scientific workloads. This awareness of how the platform evolved has guided the structure and emphasis of these notes, which focus on the mechanisms that survived because they remained useful across changing hardware and computing environments.


Before electronic digital computers, many scientific and engineering problems were addressed using analog machines. Mechanical integrators, differential analyzers (such as Vannevar Bush’s machine at MIT in the 1930s), and later electronic analog computers represented quantities as continuous voltages or mechanical positions. These systems were well suited to solving differential equations in real time, but precision was limited, reconfiguration was manual, and reproducibility depended on physical calibration.

The transition to digital computing replaced continuous physical representation with discrete binary states. Instead of voltages representing quantities directly, information was encoded in bits. This allowed exact reproducibility, programmable control flow, and the separation of hardware from algorithmic description. Machines such as ENIAC (1945) and EDVAC introduced stored-program architectures; later commercial systems like the IBM 701 (1952) and IBM 7090 (1959) became central to scientific institutions.

These early digital systems operated in batch mode. Programs were prepared on punched cards or magnetic tape and submitted to operators. Jobs were executed sequentially, often overnight. The dominant concern was efficient use of extremely expensive hardware. Early supervisory programs automated loading and job sequencing, but there was no interactivity and minimal abstraction beyond sequential execution.

In the early 1960s, time-sharing systems changed this model. At MIT, CTSS (Compatible Time-Sharing System, 1961) allowed multiple users to interact with a single machine through terminals. The operating system rapidly switched between users, providing the illusion of exclusive access. Multics (begun in 1964 by MIT, Bell Labs, and General Electric) extended this approach with hierarchical file systems, dynamic linking, segmented memory, and fine-grained access control. Multics was technically ambitious and introduced many ideas that became standard, even though it did not achieve broad commercial success.

UNIX originated directly from this environment. In 1969, Ken Thompson at Bell Labs began implementing a simpler system on a DEC PDP-7 after Bell Labs withdrew from the Multics project. Dennis Ritchie joined the effort soon after. Early UNIX versions were written in assembly language, but between 1972 and 1973 Ritchie developed the C programming language, and UNIX was largely rewritten in C.

The connection between C and UNIX is fundamental. C was designed as a systems programming language that provided low-level memory access through pointers, efficient mapping to machine instructions, and minimal runtime overhead. UNIX provided the real-world system in which C was refined and used extensively. The language and the operating system co-evolved. Kernighan and Ritchie’s 1978 book *The C Programming Language* standardized the language and disseminated it widely. Because UNIX was written in C rather than assembly, it became portable across hardware architectures, a critical factor in its spread.

During the 1970s, UNIX was adopted in universities under source licenses from AT&T. At the University of California, Berkeley, the Computer Systems Research Group developed the Berkeley Software Distribution (BSD). BSD introduced major improvements, including virtual memory support for the VAX architecture and, in the early 1980s, a TCP/IP networking stack. That networking implementation became foundational for the modern Internet.

The UNIX programming model emphasized a small set of mechanisms: process creation with `fork()`, program replacement with `exec()`, byte-stream I/O through file descriptors, and program composition using pipes. The system call interface was compact and directly accessible from C. This simplicity reduced complexity and encouraged portability.

In the 1980s, multiple commercial UNIX variants appeared. AT&T developed System V; BSD evolved independently. Vendors such as Sun Microsystems (SunOS, later Solaris), Silicon Graphics (IRIX), Hewlett-Packard (HP-UX), IBM (AIX), and Digital Equipment Corporation (Ultrix) shipped UNIX workstations widely used in scientific and engineering environments. These systems supported C and Fortran compilers, numerical libraries, and early graphical tools.

Graphical interfaces in the UNIX world were shaped by the X Window System, first released in 1984 at MIT. X implemented a network-based client–server model: applications (clients) could run on one machine while the display server ran on another. This separation allowed remote execution with local visualization, matching the distributed computing environments common in universities and laboratories. X became the standard graphical environment across UNIX systems and reinforced the network-oriented design of the ecosystem.

The early 1990s saw the emergence of widely deployed 64-bit architectures. Digital Equipment Corporation’s DEC Alpha (introduced in 1992) was one of the first commercially significant 64-bit processors. Larger address spaces enabled processes to manipulate substantially more memory, which became increasingly important for large-scale simulation and data analysis. Other 64-bit architectures followed, including MIPS, SPARC, and IBM POWER. Eventually, commodity x86 systems adopted 64-bit extensions (x86-64), bringing large address spaces to mainstream hardware.

In parallel, personal computing developed around the IBM PC (1981) and Intel processors. Early PC operating systems such as MS-DOS lacked memory protection and preemptive multitasking. Over time, Microsoft Windows incorporated more advanced kernel features, but its architecture and programming interfaces differed from traditional UNIX systems.

A major shift occurred in 1991 when Linus Torvalds began developing the Linux kernel for Intel 80386 processors. Combined with GNU userland tools developed by the Free Software Foundation, Linux formed a complete UNIX-like operating system compatible with POSIX standards. Running on inexpensive IBM-compatible hardware and distributed with source code, Linux spread rapidly in academic and research environments.

At the same time, NeXT, founded by Steve Jobs in 1985, developed NeXTSTEP, built on the Mach microkernel from Carnegie Mellon University combined with BSD components. When Apple acquired NeXT in 1997, this system evolved into Mac OS X (released in 2001), now macOS, which remains based on UNIX foundations.

By the late 1990s and early 2000s, UNIX-like systems—especially Linux—dominated scientific computing. Clusters constructed from commodity x86 machines replaced many proprietary UNIX workstations. The Message Passing Interface (MPI), standardized in the mid-1990s, relied on the UNIX process and networking model to implement distributed-memory parallelism. Today, most supercomputers run Linux or UNIX-derived systems.

The progression from analog machines to digital stored-program computers, from batch processing to time sharing, from assembly-based systems to C-based portable kernels, and from proprietary workstations to Linux on commodity hardware reflects a continuous refinement of abstractions. Processes, virtual memory, file descriptors, signals, and network sockets have persisted across hardware generations because they solve fundamental resource management problems in a hardware-independent way.

The tight coupling between C and UNIX ensured that these abstractions were exposed through a simple, efficient programming interface. That interface remains central to modern computational science.
