# SIMD vectorisation of the D3Q19 collision kernel (SoA layout)

We now take the scalar D3Q19 collision kernel and **vectorise across lattice sites** using SIMD. This is the natural direction because of the **SoA layout**:

[
f[q*N + i] ;;\text{is contiguous in}; i
]

So a SIMD load brings in `f_q` for multiple sites at once.

We will write one explicit SIMD implementation for **x86 AVX (256-bit)** (4 doubles at a time). The same structure applies to:

* **SSE2** (2 doubles at a time),
* **ARM NEON** (2 doubles at a time),
* **ARM SVE** (vector-length agnostic with predication).


## Strategy: vectorise across sites

For a SIMD width `VL` (VL=4 for AVX+double):

For each vector of sites `i..i+VL-1`:

1. Accumulate vector moments:

   * `rho = sum_q fq`
   * `jx  = sum_q fq * cx[q]` (similarly `jy, jz`)
2. Compute `ux, uy, uz` as vectors (`ux = jx / rho`)
3. For each `q`, compute:

   * `cu = cx[q]*ux + cy[q]*uy + cz[q]*uz`
   * `feq = w[q]*rho*(1 + 3cu + 4.5cu^2 - 1.5u^2)`
   * `f_out = (1-omega)*fq + omega*feq`  (**FMA-friendly**)

Key point: **SIMD pays off most when you keep the inner loop simple** and allow the compiler (or intrinsics) to use FMA (`fmadd`) in the polynomial and collision update.

## AVX2 kernel

Add this to your file (keep the same `cx, cy, cz, w` arrays and SoA layout):

```c
#if defined(__x86_64__) || defined(_M_X64)
#include <immintrin.h>
#endif

void collide_d3q19_avx_fma(int N,
                           double * RESTRICT f_out,
                           const double * RESTRICT f_in,
                           double omega)
{
#if defined(__x86_64__) || defined(_M_X64)
    const int VL = 4; // __m256d
    int i = 0;

    const __m256d vone  = _mm256_set1_pd(1.0);
    const __m256d vthree = _mm256_set1_pd(3.0);
    const __m256d vfourp5 = _mm256_set1_pd(4.5);
    const __m256d vminusp1p5 = _mm256_set1_pd(-1.5);

    const __m256d vomega = _mm256_set1_pd(omega);
    const __m256d vone_minus_omega = _mm256_set1_pd(1.0 - omega);

    // Vector loop over sites (leave tail + edges to scalar)
    // We ignore i=0 and i=N-1 boundaries in this collision-only benchmark anyway,
    // but here collision is local so we can include all i.
    for (; i + (VL-1) < N; i += VL) {

        __m256d rho = _mm256_setzero_pd();
        __m256d jx  = _mm256_setzero_pd();
        __m256d jy  = _mm256_setzero_pd();
        __m256d jz  = _mm256_setzero_pd();

        // --- moments: sum over q ---
        for (int q = 0; q < 19; q++) {
            const double *fq_ptr = &f_in[q*(size_t)N + i];
            __m256d fq = _mm256_loadu_pd(fq_ptr);

            rho = _mm256_add_pd(rho, fq);

            // Multiply by cx[q], cy[q], cz[q] (each in {-1,0,1})
            if (cx[q] == 1)      jx = _mm256_add_pd(jx, fq);
            else if (cx[q] == -1) jx = _mm256_sub_pd(jx, fq);

            if (cy[q] == 1)      jy = _mm256_add_pd(jy, fq);
            else if (cy[q] == -1) jy = _mm256_sub_pd(jy, fq);

            if (cz[q] == 1)      jz = _mm256_add_pd(jz, fq);
            else if (cz[q] == -1) jz = _mm256_sub_pd(jz, fq);
        }

        // ux = jx/rho etc.
        __m256d inv_rho = _mm256_div_pd(vone, rho);
        __m256d ux = _mm256_mul_pd(jx, inv_rho);
        __m256d uy = _mm256_mul_pd(jy, inv_rho);
        __m256d uz = _mm256_mul_pd(jz, inv_rho);

        // u2 = ux^2 + uy^2 + uz^2
        __m256d ux2 = _mm256_mul_pd(ux, ux);
        __m256d uy2 = _mm256_mul_pd(uy, uy);
        __m256d uz2 = _mm256_mul_pd(uz, uz);
        __m256d u2  = _mm256_add_pd(_mm256_add_pd(ux2, uy2), uz2);

        // --- collision over q ---
        for (int q = 0; q < 19; q++) {
            const double *fq_ptr_in = &f_in[q*(size_t)N + i];
            double *fq_ptr_out      = &f_out[q*(size_t)N + i];

            __m256d fq = _mm256_loadu_pd(fq_ptr_in);

            // cu = cx*ux + cy*uy + cz*uz  (cx,cy,cz in {-1,0,1})
            __m256d cu = _mm256_setzero_pd();
            if (cx[q] == 1)      cu = _mm256_add_pd(cu, ux);
            else if (cx[q] == -1) cu = _mm256_sub_pd(cu, ux);

            if (cy[q] == 1)      cu = _mm256_add_pd(cu, uy);
            else if (cy[q] == -1) cu = _mm256_sub_pd(cu, uy);

            if (cz[q] == 1)      cu = _mm256_add_pd(cu, uz);
            else if (cz[q] == -1) cu = _mm256_sub_pd(cu, uz);

            // Polynomial: p = 1 + 3*cu + 4.5*cu^2 - 1.5*u2
            __m256d cu2 = _mm256_mul_pd(cu, cu);

            // p = (1 - 1.5*u2) + cu*(3 + 4.5*cu)
            __m256d p = _mm256_fmadd_pd(vminusp1p5, u2, vone);     // p = 1 + (-1.5)*u2
            __m256d t = _mm256_fmadd_pd(vfourp5, cu, vthree);      // t = 3 + 4.5*cu
            p = _mm256_fmadd_pd(cu, t, p);                         // p = p + cu*t

            // feq = w[q] * rho * p
            __m256d vw = _mm256_set1_pd(w[q]);
            __m256d feq = _mm256_mul_pd(_mm256_mul_pd(vw, rho), p);

            // f_out = (1-omega)*fq + omega*feq   (use FMA)
            __m256d outv = _mm256_fmadd_pd(vomega, feq, _mm256_mul_pd(vone_minus_omega, fq));
            _mm256_storeu_pd(fq_ptr_out, outv);
        }
    }

    // scalar tail
    for (; i < N; i++) {
        double rho = 0.0, jx = 0.0, jy = 0.0, jz = 0.0;
        for (int q = 0; q < 19; q++) {
            double fq = f_in[q*(size_t)N + i];
            rho += fq;
            jx += fq * (double)cx[q];
            jy += fq * (double)cy[q];
            jz += fq * (double)cz[q];
        }
        double ux = jx / rho, uy = jy / rho, uz = jz / rho;
        double u2 = ux*ux + uy*uy + uz*uz;

        double one_minus_omega = 1.0 - omega;
        for (int q = 0; q < 19; q++) {
            double fq = f_in[q*(size_t)N + i];
            double cu = (double)cx[q]*ux + (double)cy[q]*uy + (double)cz[q]*uz;
            double p = (1.0 - 1.5*u2) + cu*(3.0 + 4.5*cu);
            double feq = w[q] * rho * p;
            f_out[q*(size_t)N + i] = one_minus_omega*fq + omega*feq;
        }
    }

    sink += f_out[0*(size_t)N + (N/2)];
#else
    // Non-x86 fallback
    collide_d3q19_fma_friendly(N, f_out, f_in, omega);
#endif
}
```

In summary:

* SIMD vectorises **across sites** thanks to contiguous memory allocation.
* moment sums are vector accumulations (no horizontal reductions inside SIMD)
* we avoid multiply-by-{-1,0,1} using add/sub (cheap and clear)
* the equilibrium polynomial is written in a way to **create obvious FMAs**
* collision update uses a clear FMA form

## Verify SIMD + FMA actually happened

### Check for vector instructions

```bash
objdump -d -Mintel lb_avx | grep -E "ymm|vaddpd|vmulpd|vmovupd" | head
```

### Check for FMA

```bash
objdump -d -Mintel lb_avx | grep -i vfmadd | head
```

If you don’t see `vfmadd*`:

* confirm `-mfma` is enabled,
* confirm you compiled the AVX function (not falling back),
* ensure you didn’t accidentally build with `-ffp-contract=off`.


# What to measure and what to expect

Run at least two regimes:

### Regime A: “more compute-sensitive” (cache friendlier)

```bash
./lb_avx $((1<<18)) 200
```

### Regime B: “more bandwidth-sensitive” (streaming)

```bash
./lb_avx $((1<<22)) 50
```

Expected pattern:

* SIMD often gives a clear speedup in both regimes.
* FMA’s extra benefit is most visible in the more compute-sensitive regime.
* In the streaming regime, speedup is limited by how fast you can move `19×` doubles in/out.
