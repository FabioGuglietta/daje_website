Stack and Heap Memory

When a program runs, the operating system gives it a portion of memory called its address space. Two important regions in that space are the stack and the heap.

Stack¶

  • Used for storing function call frames and local variables.

  • Managed automatically (LIFO – last-in, first-out).

  • Has limited size — large allocations can cause a stack overflow.

Note

LIFO – Last In, First Out

The stack follows the LIFO principle: the last item added is the first one removed.
For example, when a function is called, its local variables and return address are pushed onto the stack.
When the function ends, that frame is popped off — returning control to the previous function.
This ensures function calls return in the correct order.

An example in pseudo code:

function MAIN:
    call A

function A:
    call B

function B:
    print "Inside B"

This is what happens in memory (the call stack):

  1. main() starts → its stack frame is pushed

  2. A() is called → its frame is pushed on top

  3. B() is called → its frame is pushed on top

  4. B() finishes → its frame is popped

  5. A() resumes and finishes → its frame is popped

  6. main() resumes → finally its frame is popped

The last function called (B) is the first to finish.
This is a Last In, First Out (LIFO) behavior.

Heap¶

  • Used for dynamic memory allocation (e.g., using malloc in C or allocate in Fortran).

  • Managed manually by the programmer or language runtime.

  • More flexible in size, but also more prone to memory leaks or fragmentation.

Stack vs Heap: The Core Differences¶

FeatureStackHeap
StructureLast In, First Out (LIFO)Unstructured
Memory ManagementAutomaticManual or Garbage Collected
Cache LocalityHigh (contiguous blocks)Low (scattered objects)
Thread SafetyThread-localShared across threads
Size & FlexibilityFixed size per threadLarge, dynamic size
RiskStack overflowFragmentation, memory leaks
Warning

Stack vs Heap speed¶

Often it is written that accessing memory on the stack is faster than that allocated on the heap. This might have been true on older machines, but nowadays this is not a problem anymore. Aliasing (when the compiler does not know a priori whether two or more addresses might point to overlappling memory segments) is a much more serious issue.

Tip

If you need to use a large portion of memory as, e.g., a buffer for some calculation, avoid (if possible) to keep allocating/deallocating it, as might slow down the code due to the allocation overhead and memory fragmentation. Instead, allocate it once at the beginning and reuse it later. If you need to grow the memory you can always reallocate it when needed.

Warning

Common Issues¶

  • Memory leaks: when a program allocates memory and never releases it.

  • Fragmentation: inefficient use of memory due to small unused gaps.

  • Stack overflow: when too much memory is used on the call stack (e.g., due to deep recursion).

  • Thrashing: excessive paging activity due to insufficient RAM.
