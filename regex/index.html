Regular Expressions (regex)

A regular expression, often abbreviated as regex, is a compact way to describe a text pattern.

Regular expressions are used to search, select, validate, or modify text.

For example, a regular expression can describe:

  • all lines containing a number;

  • all filenames ending in .dat;

  • all words starting with data;

  • all lines beginning with #;

  • all assignments of the form parameter = value;

  • all email-like strings;

  • all numbers written in decimal notation.

Regular expressions are used by many Unix tools, including:

grep
sed
awk
less
find
perl
python

In the shell, they are especially important when using commands such as:

grep pattern file.txt
sed 's/pattern/replacement/' file.txt
awk '/pattern/ {print $0}' file.txt

Regex is not the same as shell globbing¶

Before starting, it is important to distinguish regular expressions from shell wildcards, also called globbing.

Shell globbing is used by the shell to match filenames:

ls *.dat

Here *.dat means:

all filenames ending in .dat

Regular expressions are used by programs such as grep, sed, and awk to match text inside files:

grep '.*\.dat' filelist.txt

Although they look similar, they are not the same language.

MeaningShell globRegular expression
Any sequence of characters*.*
Any single character?.
Literal dot.\.
Files ending in .dat*.dat.*\.dat$

For example:

ls *.dat

matches filenames ending in .dat.

But:

grep '*.dat' filelist.txt

does not mean the same thing. In a regular expression, * does not mean “anything”. It means “repeat the previous pattern zero or more times”.

Let’s create a file called simulation.log:

cat > simulation.log
# Simulation output
step 0 time 0.00 velocity 1.20 pressure 10.1 status OK
step 1 time 0.10 velocity 1.40 pressure 10.3 status OK
step 2 time 0.20 velocity 1.50 pressure 10.4 status WARNING
step 3 time 0.30 velocity 1.70 pressure 10.8 status OK
step 4 time 0.40 velocity 1.60 pressure 10.6 status FAILED
restart = false
output_file = results.dat
path = /home/m.sega/data
^D

Inspect it:

cat simulation.log

We will use this file for most examples.

Literal matches¶

The simplest regular expression is ordinary text.

For example:

grep 'velocity' simulation.log

prints all lines containing the word velocity.

grep 'restart' simulation.log

prints:

restart = false

In these examples, the pattern is just a literal string.

However, some characters have a special meaning in regular expressions. These include:

. * + ? ^ $ [ ] ( ) { } | \

If you want to match them literally, you may need to escape them with \.

The dot .: any single character¶

In a regular expression, the dot:

.

matches any single character.

Example:

grep 'st.p' simulation.log

This can match:

step

The dot matches exactly one character, not zero characters and not many characters.

Note

If you want to match an actual dot, escape it:

grep '0\.10' simulation.log

Without the backslash:

grep '0.10' simulation.log

the dot could match any character between 0 and 10.

Character classes: [ ... ]¶

Square brackets define a character class.

A character class matches one character chosen from a set.

For example:

[abc]

matches one character: either a, b, or c.

Example:

grep 'st[aeiou]p' simulation.log

This matches words such as:

stap
step
stip
stop
stup

if they appear in the file.

In our file, it matches:

step

because e is one of the listed characters.

Other examples of classes:

grep '[0-9]' simulation.log        # print lines containing at least one digit
grep '[a-z]' simulation.log        # print lines containing at least one lowercase letter
grep '[A-Z]' simulation.log        # print lines containing at least one uppercase letter
grep '[A-Za-z0-9]' simulation.log  # print lines containing at least one letter or digit

Negated character classes: [^ ... ]¶

Inside square brackets, a leading ^ means not.

For example:

[^0-9]

matches one character that is not a digit.

Example:

grep '[^0-9]' simulation.log

This prints lines containing at least one non-digit character.

A more useful example is:

grep '^[^#]' simulation.log

This means:

start of line → first character is not #

So it prints lines that do not begin with #.

Note

The symbol ^ has two meanings depending on position:

  • outside square brackets, ^ means beginning of line;

  • inside square brackets at the beginning, ^ means negation.

Anchors: beginning and end of line¶

Anchors do not match ordinary characters. They match positions.

Beginning of line: ^¶

The symbol:

^

matches the beginning of a line.

Example:

grep '^step' simulation.log

prints lines starting with step.

It does not match lines where step appears later in the line.

End of line: $¶

The symbol:

$

matches the end of a line.

Example:

grep 'OK$' simulation.log

prints lines ending with OK.

Empty lines¶

The pattern:

^$

matches empty lines.

Tip

To remove empty lines using grep -v:

grep -v '^$' file.txt

Repetition operators¶

Repetition operators specify how many times the previous pattern may occur.

There is a difference between basic regular expressions and extended regular expressions.

For clarity, this lecture mostly uses extended regular expressions with:

grep -E
sed -E

Zero or more: *¶

The symbol:

*

means:

zero or more repetitions of the previous pattern

Example:

a*

matches:

empty string
a
aa
aaa
...

Example:

grep -E '1\.?0*' simulation.log

This is already harder to read. The main point is that * repeats the previous element.

A very common pattern is:

.*

which means:

any character, repeated zero or more times

So:

^step.*OK$

means:

line starts with step, then anything, then ends with OK

Example:

grep -E '^step.*OK$' simulation.log

One or more: +¶

The symbol:

+

means:

one or more repetitions of the previous pattern

Example:

[0-9]+

matches one or more digits.

grep -E '[0-9]+' simulation.log

This prints lines containing at least one integer-like sequence.

Zero or one: ?¶

The symbol:

?

means:

zero or one occurrence of the previous pattern

Example:

colou?r

matches both:

color
colour

because the u is optional.

Exact number: {n}¶

The pattern:

[0-9]{3}

matches exactly three digits.

Example:

grep -E '[0-9]{3}' simulation.log

Range of repetitions: {m,n}¶

The pattern:

[0-9]{2,4}

matches from two to four digits.

Examples:

12
123
1234

At least m repetitions: {m,}¶

The pattern:

[0-9]{2,}

matches at least two digits.

Basic versus extended regular expressions¶

Unix tools often distinguish between:

  • basic regular expressions;

  • extended regular expressions.

With basic regular expressions, some operators must be escaped.

With extended regular expressions, they can be written more naturally.

MeaningBasic regexExtended regex
One or more\++
Zero or one\??
Grouping\(...\)(...)
Alternative|`
Repetition range\{m,n\}{m,n}

Examples:

grep '[0-9]\+' simulation.log

uses basic regex syntax.

grep -E '[0-9]+' simulation.log

uses extended regex syntax.

For teaching and most practical use, grep -E and sed -E are usually easier to read.

Alternatives: |¶

The symbol:

|

means or in extended regular expressions.

Example:

grep -E 'WARNING|FAILED' simulation.log

prints lines containing either WARNING or FAILED.

Another example:

grep -E 'restart|output_file|path' simulation.log

prints lines containing any of these parameter names.

Groups: ( ... )¶

Parentheses group parts of a regular expression.

Example:

grep -E 'status (OK|WARNING|FAILED)' simulation.log

This means:

match status followed by either OK, WARNING, or FAILED

Groups are useful when combined with alternatives or repetitions.

Example:

(ab)+

matches:

ab
abab
ababab

because the whole group ab is repeated.

Word boundaries¶

Sometimes we want to match a word, not just a sequence of characters inside a longer word.

For example, the pattern:

cat

would match:

cat
concatenate
category

To match complete words, use word-boundary syntax. The exact syntax depends on the tool.

With grep -E, a common option is:

grep -w 'cat' file.txt

The option -w means “match whole words”.

Example:

grep -w 'step' simulation.log

This matches step as a word.

In sed, GNU implementations often support:

\b

as a word boundary with extended regex, but portability can vary.

A portable approach is to use explicit separators, for example:

(^|[[:space:]])word([[:space:]]|$)

This means:

word preceded by beginning of line or whitespace,
and followed by whitespace or end of line

POSIX character classes¶

POSIX character classes are portable symbolic names for common character sets.

They are written inside double square brackets:

[[:digit:]]
[[:alpha:]]
[[:space:]]

Common classes:

ClassMeaning
[[:digit:]]digit, similar to [0-9]
[[:alpha:]]letter
[[:lower:]]lowercase letter
[[:upper:]]uppercase letter
[[:alnum:]]letter or digit
[[:space:]]whitespace
[[:blank:]]space or tab
[[:punct:]]punctuation
[[:xdigit:]]hexadecimal digit

Examples:

grep -E '[[:digit:]]+' simulation.log

prints lines containing one or more digits.

grep -E '^[[:space:]]*#' simulation.log

prints lines that start with optional whitespace followed by #.

This is useful for matching comment lines.

grep -Ev '^[[:space:]]*#' simulation.log

prints lines that are not comments.

Matching numbers¶

Regular expressions are often used to match numbers.

Integer¶

An integer can be matched with:

[0-9]+

Example:

grep -E '[0-9]+' simulation.log

Optional sign¶

To allow an optional + or - sign:

[+-]?[0-9]+

This matches:

10
-10
+10

Decimal number¶

A simple decimal number can be matched with:

[+-]?[0-9]+\.[0-9]+

This matches:

0.10
-3.14
+2.71
Note

The dot is escaped as \. because an unescaped dot means “any character”.

Integer or decimal¶

To match either an integer or a decimal:

[+-]?[0-9]+(\.[0-9]+)?

This means:

optional sign
one or more digits
optional decimal part

Example:

grep -E '[+-]?[0-9]+(\.[0-9]+)?' simulation.log

Scientific notation¶

A simple pattern for scientific notation is:

[+-]?[0-9]+(\.[0-9]+)?([eE][+-]?[0-9]+)?

This matches values such as:

1
1.0
-1.23
1e-3
2.5E+6

This is useful for simulation outputs.

Matching assignments: parameter = value¶

Many input files contain lines such as:

dt = 0.01
nsteps = 100
restart = false

A simple regex for this form is:

^[[:space:]]*[A-Za-z_][A-Za-z0-9_]*[[:space:]]*=

Meaning:

beginning of line
optional whitespace
parameter name starting with a letter or underscore
more letters, digits, or underscores
optional whitespace
=

Example:

grep -E '^[[:space:]]*[A-Za-z_][A-Za-z0-9_]*[[:space:]]*=' simulation.log

This prints assignment-like lines:

restart = false
output_file = results.dat
path = /home/m.sega/data

To select a specific parameter:

grep -E '^[[:space:]]*restart[[:space:]]*=' simulation.log

Regex in grep¶

The command grep prints lines matching a pattern.

General syntax:

grep [options] 'pattern' file

Useful options:

OptionMeaning
-Euse extended regular expressions
-iignore case
-vinvert match
-nshow line numbers
-ccount matching lines
-wmatch whole words
-rsearch recursively in directories

Examples:

grep -E 'WARNING|FAILED' simulation.log
grep -nE '^step' simulation.log
grep -Ev '^[[:space:]]*#' simulation.log
grep -cE 'status OK$' simulation.log

Regex in sed¶

In sed, regular expressions are used to select lines and to substitute text.

General substitution syntax:

sed -E 's/pattern/replacement/' file

Example:

sed -E 's/status OK/status SUCCESS/' simulation.log

Replace all numbers with NUMBER:

sed -E 's/[+-]?[0-9]+(\.[0-9]+)?/NUMBER/g' simulation.log

Delete comment lines:

sed -E '/^[[:space:]]*#/d' simulation.log

Print only assignment lines:

sed -E -n '/^[[:space:]]*[A-Za-z_][A-Za-z0-9_]*[[:space:]]*=/p' simulation.log

19. Capturing groups and backreferences¶

Capturing groups allow us to reuse matched text.

With extended regular expressions, groups are written as:

(...)

The captured groups can be reused as:

\1
\2
\3

Example file:

cat > names.txt
Boltzmann Ludwig
Einstein Albert
Curie Marie
^D

Swap surname and name:

sed -E 's/([A-Za-z]+) ([A-Za-z]+)/\2 \1/' names.txt

Output:

Ludwig Boltzmann
Albert Einstein
Marie Curie

Here:

([A-Za-z]+)

captures the first word.

The second:

([A-Za-z]+)

captures the second word.

The replacement:

\2 \1

prints the second group first, then the first group.

Capturing assignments¶

Create:

cat > inputfile
dt = 0.01
nsteps = 100
restart = false
^D

Transform assignments into another format:

sed -E 's/^([A-Za-z_][A-Za-z0-9_]*)[[:space:]]*=[[:space:]]*(.*)$/\1 -> \2/' inputfile

Output:

dt -> 0.01
nsteps -> 100
restart -> false

Explanation:

group 1: parameter name
=
group 2: value

The & symbol in replacements¶

In a sed replacement, the symbol:

&

means:

the entire matched text

Example:

echo "value 123" | sed -E 's/[0-9]+/[&]/'

Output:

value [123]

The pattern [0-9]+ matches 123.

The replacement [&] means:

the matched text inside brackets

Another example:

echo "pressure 10.5" | sed -E 's/[+-]?[0-9]+(\.[0-9]+)?/<&>/'

Output:

pressure <10.5>
Note

Note that in the previous command, the matched text is only the value of the pressure.

Greedy matching¶

Most Unix regular expressions are greedy: they match as much as possible.

Example:

echo "a <first> b <second> c" | sed -E 's/<.*>/TAG/'

Output:

a TAG c

The pattern:

<.*>

does not stop at the first >. It matches from the first < to the last >.

To match only inside one pair of angle brackets, use a negated character class:

echo "a <first> b <second> c" | sed -E 's/<[^>]*>/TAG/'

Output:

a TAG b <second> c

Here:

[^>]*

means:

any number of characters that are not >

This is a common technique.

Escaping special characters¶

Some characters have special meaning in regex:

. * + ? ^ $ [ ] ( ) { } | \

To match them literally, escape them with \.

Literal characterRegex
.\.
*\*
+\+ in extended regex, or literal inside [+]
?\?
[\[
]\]
(\(
)\)
$\$
^\^ except inside some contexts
\\\

Example:

grep -E 'results\.dat' simulation.log

matches:

results.dat

Example:

grep -E '/home/m\.sega/data' simulation.log

matches:

/home/m.sega/data

The slash / is not special in regex itself, but it is often used as a delimiter in sed. In sed, for paths it is often better to use another delimiter:

sed -E 's|/home/m.sega/data|/scratch/m.sega/data|' simulation.log

Quoting regex in the shell¶

Regular expressions should usually be placed inside single quotes:

grep -E '[0-9]+' file.txt

Single quotes prevent the shell from interpreting special characters.

For example, this is safe:

grep -E '^[[:space:]]*#' file.txt

Avoid writing:

grep -E ^[[:space:]]*# file.txt

because the shell may interpret some characters before grep receives them.

Important

Use double quotes only when you intentionally want shell variables to be expanded:

pattern="WARNING|FAILED"
grep -E "$pattern" simulation.log
